1. 项目概览

「上课啦」是一款面向杭州电子科技大学学生的课堂签到自动化安卓应用。核心目标：在老师公布 4 位签到码后的 15 秒黄金窗口内，通过语音识别自动提取签到码并注入 WebView 完成签到，把"听码 → 掏手机 → 输码 → 点签到"的手动操作压缩到接近零。

3. 系统架构

架构为单 Activity + 多职责类模式：MainActivity 是核心调度器（约 3700 行），持有 WebView、签到面板、键盘、状态机；其余 7 个类为独立功能模块，通过回调/直接调用与 MainActivity 交互。无 Service、无 BroadcastReceiver、无 Fragment。

4. 核心模块详解

4.1 MainActivity.kt（161KB · ~3700 行）

整个应用的大脑，承担以下职责：

  • WebView 管理：加载签到页、登录态探测（probe login）、页面状态轮询（pollTick 每秒）、URL 变化监听
  • 签到面板 UI：四位码槽、大数字键盘、时钟/经纬度/课程信息区、成功覆盖页、无效弹窗、首次引导流程
  • 语音调度：maybeAutoListen 哨兵（8 项条件检查）、onResult 切片处理、extractCode 本地提取、maybeLlmExtract LLM 兜底、submitCode 提交
  • 结果判定状态机：filling → pollFillResult（120ms 轮询注入结果）→ pollTick（每秒查 URL 跳转）→ 成功/无效分支
  • 登录链路：CAS 跳转探测、自动填表、SSO 循环防护、登录成功后切回面板
  • 生命周期：onResume/onPause 控制监听启停，后台立即停止麦克风

4.2 MiMoSpeechEngine.kt（19KB）

小米 MIMO 云端语音识别引擎，采用转写 + 综合判断两步架构：

  • 录音层：AudioRecord 持续采集 16kHz PCM，写入 10 秒环形缓冲区（ByteArray 320KB），全程不中断
  • 切片层：首片等 6 秒（FIRST_SLICE_MS），之后每 3 秒（SLICE_MS）截取最近 10 秒（WINDOW_MS），相邻片重叠 7 秒降低断句概率
  • 上传层：2 线程池并行上传 HttpURLConnection，含静音片也上传（避免轻声漏识别），Base64 编码 PCM
  • 转写模型：mimo-v2.5-asr（中文语音转文字）
  • 综合模型：mimo-v2.6-flash（多模态对话，从累积转写中提取 4 位签到码）
  • 防残留：stopped 标志位，停止后所有回调作废，杜绝上一轮识别结果混入新一轮

4.3 SignInjector.kt（24KB）

注入 WebView 的 JavaScript 引擎，针对 skl.hdu.edu.cn 前端结构定制：

  • 页面探测（JS_DETECT_STATE）：检测密码框、验证码、签到按钮、定位提示、URL hash，返回 JSON
  • 自动登录：精确选择器填学号密码，触发 input/change/keyup/ionInput 完整事件序列确保 Angular model 同步，等 800ms 后点登录
  • 四位码盲输（jsFillCode）：Vant 数字键盘只响应 touch 事件，用合成 TouchEvent 逐键模拟点击（180ms 间隔），通过统计已填圆点数量校验（不能读文本——密码框是圆点），最多清残留重试 2 轮
  • 关键修复：v1.x 曾因"读取文本校验"导致 2588 变成 2222（重复按同一键），改为圆点计数后解决

4.4 CredentialStore.kt（7KB）

基于 Android Keystore 的加密存储：

  • 学号密码用 AES/GCM 加密，密钥存 Keystore（硬件级安全），密文存 SharedPreferences
  • 同时管理所有偏好设置：API Key、模型选择、主题、自动监听开关、课表数据、免责声明同意记录

4.5 SettingsActivity.kt（38KB）

独立设置页，分块布局：账号密码、语音引擎（MIMO API Key / 模型选择 / 自动监听）、课表导入（ICS）、主题选择（5 套色板卡片）、调试日志（可滚动 + 导出）、弹窗测试按钮。

4.6 ScheduleParser.kt（2.5KB）

ICS 课表文件解析器，提取 VEVENT 中的课程名、时间、地点，一次导入永久保存。

4.7 ThemePalette.kt（8KB）

5 套主题色板定义：墨青（默认）、朱砂·国潮、原木·暖阳、石墨·极简、极光·青绿。每套包含强调色、浅底、键盘文字色、错误色、成功色、分隔线色。运行时动态切换，明暗模式自适应。

4.8 DebugLog.kt（1.4KB）

轻量调试日志收集器，appendLog 追加带时间戳的日志行，支持导出为 txt 到 Download 目录。

5. 语音识别签到全链路（核心）

这是本 App 最复杂、迭代最多的子系统（v3.0.3 → v3.0.8 共 6 个版本专门优化）。完整链路如下：

A. 哨兵检查
8 项条件全满足才启动
→
B. 录音切片
10s 环形缓冲 · 首片6s · 之后3s/片
→
C. ASR 转写

D. 本地提取

5.1 启动哨兵（maybeAutoListen）

以下 8 项必须同时满足才启动麦克风监听，缺一则状态栏显示对应原因：

  1. 设置中自动语音监听开关开启
  2. 已填写 MIMO API Key
  3. 已授予麦克风权限
  4. 签到面板在前台显示（signPanelShown = true）
  5. App 不在后台（hasWindowFocus）
  6. 当前不在提交等待状态（!filling）
  7. 未显示无效弹窗
  8. 签到就绪（signReady = true）

5.2 本地快速路径 extractCode（v3.0.8 现行规则）

每片 ASR 转写到达后，优先走本地提取（零延迟），步骤：

  1. 剔除语气词：啊/哦/嗯/呢/嘛/的/了/个/是/呀/啦/哈/喂/诶/好
  2. 英文数字替换：zero~nine → 0~9（正则边界匹配）
  3. 提取所有数字段：标准数字字 = 0-9 + 零洞幺一两三四五六七八九；"十百千"和同音字不算
  4. 段间拼接判定（v3.0.6 新增，v3.0.7 修复）：两段数字之间只隔标点/空白（逗号顿号句号等）则拼接；中间夹任何实义文字（"第一次""签到码是"）则不拼。文本开头的非数字前缀直接丢弃
  5. 合并段判定：
    • 合并段 >4 位且循环前缀重复（前4位+剩余位构成循环，如 1234123 → 1234）→ 取前 4 位，本地命中
    • 合并段恰好 4 位且只有一个 → 本地命中
    • 多个 4 位段无法确定 → 交 LLM
    • 其余 → 交 LLM
  6. 尾部防误杀（findTailOfLongerSegment）：命中的 4 位若等于历史转写里更长段的末尾（如"一四七八"是"八一四七八"的尾部），说明是第二遍报码被截断 → 从历史长段取前 4 位
典型场景走查（v3.0.7 实测通过）：
转写 "签到码是一二三，四一二三。" → 剔除语气词 → 数字段 [一二三, 四一二三]，间隔 "，"（标点可拼）→ 合并为 1234123 → 循环检测：前4=1234，剩余 123 是 1234 的前缀 → 本地命中 1234，跳过 LLM，零延迟提交。

5.3 LLM 兜底（maybeLlmExtract）

本地没把握时，把 heardPool（最近 10 条转写，含时间戳）交给 mimo-v2.6-flash，提示词规则：

  • 只提取老师明确报出的签到码，闲聊/口头禅中的数字忽略
  • 重复报码取开头完整的一组（8517851 → 8517，后段 851 是第二遍被截断的前缀）
  • 2-3 位不完整片段输出"无"，不猜测
  • 谐音字严禁猜测（八≠百/吧，四≠是/十）
  • 3 位 + 1 位跨片可拼接（三八三 + 八 → 三八三八）
  • 宁可输出"无"也不猜

输出必须恰好 4 位纯数字才接受，否则丢弃继续监听。llmExtractBusy 防重入，上一次未返回时不重复请求。

5.4 提交与结果判定

  1. submitCode：filling=true → 立即停监听 → 大数字浮层（v3.0.8 已删弹跳动画）→ jsFillCode 盲输
  2. pollFillResult：每 120ms 查注入结果，上限 60 次（约 7 秒）
  3. pollTick（每秒）：URL 跳到 #/sign/in/detail → 成功覆盖页（彩带）；5 秒未跳 → 无效弹窗（小字"或网络超时"）；再缓冲 3 秒后停止检测

7. UI/UX 设计体系

7.1 视觉系统（v3.0.0 大改定版）

  • 主界面：标题栏 22sp + 主题色分隔线；信息区（签到就绪/时钟/经纬度/课程）字阶 17-24sp；四位码槽独立数字位（v3.0.8 删弹跳动画，静态显示）；键盘键高 62dp、圆角 22、数字 28sp
  • 成功覆盖页：反色印章徽章（绿环白心）+ 30sp 大标题 + 圆角 20 考勤卡（旷课学时/课程名）
  • 无效弹窗：警示图标 + "签到码无效" + 小字"或网络超时" + 重新输入按钮
  • 设置页：分块圆角 20 + 标题加粗 + 输入框圆角 14 + 主题选择器改色板卡片（强调色圆点 + 选中整卡变色 + 投影）
  • 开屏：品牌色渐变 + 图标弹入 + 四位码槽逐个点亮（v2.0.x 精简后保留）

7.2 首次引导流程

  1. 免责声明：全屏遮罩卡片弹窗，须滑动到底才能点同意（未滑到底按钮灰色 + Toast 提示），不同意自动退出 App；同意记录存本地，只弹一次
  2. 权限引导：麦克风 + 定位权限，授予失败引导再次点击
  3. 设置页：首次进入隐藏左上角返回（禁用系统返回手势），只保留右上角保存，防止用户乱点；WebView 延迟至保存后才加载（避免后台加载导致时机问题）

7.3 震动反馈

仅三个场景触发：输入数字时（清脆短震）、提示错误时（快速两下）、签到成功时。v3.x 收敛了震动频率，避免过度反馈。

9. 已知问题与技术债

P0 · 提交后 URL 不跳转：多次课堂实测中，正确签到码（如 8147、1234）提交后页面输入框显示正确数字，但 URL 不跳 #/sign/in/detail，5 秒后弹无效弹窗。页面抓取未显示"签到码不存在"（说明码是对的），但也未跳转。jsFillCode 只逐键填码、从不点击"签到"按钮——可能依赖页面自动提交，但自动提交未触发。此问题用户已确认暂缓修复。
P1 · LLM 响应延迟不稳定：mimo-v2.6-flash 综合判断响应时间 3-17 秒波动，本地快速路径已覆盖大部分场景（4 位/循环重复/拼接），但多段歧义场景仍需等 LLM。
P1 · MainActivity 单文件过大：161KB / ~3700 行，承担 UI + 状态机 + 语音调度 + 登录 + 生命周期，可维护性下降。建议拆分为 SignPanelController、LoginController、ResultWatcher 等。
P2 · 其他技术债：
  • release 构建用 debug 签名（自用可接受，分发需正式签名）
  • 无签到历史持久化（签完即忘）
  • 无单元测试（提取逻辑 extractCode 适合写纯函数测试）
  • ASR 同音字识别依赖模型质量，"四/是""八/吧"在嘈杂教室仍可能误转
  • 课表为手动 ICS 导入，未对接杭电教务系统自动获取

总结：这是一个由真实课堂需求驱动、快速迭代的个人工具项目。最大的技术亮点是语音识别签到码的本地+LLM 双层提取架构——通过连续 4 位门槛、循环重复检测、标点间隔拼接、尾部防误杀四层本地规则，把绝大多数场景的延迟从 LLM 的 3-17 秒压缩到零延迟，同时用 LLM 兜底歧义场景。最大的待解决问题是提交后页面不跳转（P0）和 MainActivity 单文件膨胀（可维护性）。
